## 2. 방향

**한 문장**: 외국인이 서울의 한글을 "읽을 수 있게 되는" 순간을 페이지 자체로 보여 준다. 큰 문장 한가운데에 한글 간판·메뉴 영상 조각이 단어 자리를 차지하고, 그 뜻이 문장으로 완성된다.

- 아이디어 문장: *이 페이지에서 **서울의 한글(궁궐 안내판, 식당 메뉴, 골목 표지)** 은 **제목 문장 속 단어 자리에 박힌 영상 조각** 이 된다.*
  경쟁사 테스트: Spectari를 넣으면 성립하지 않는다(그들은 "세계 어디서나"를 판다). 우리는 서울 한 곳, 한글→영어 한 방향이다.
- 무드: 맑은 오전의 서울, 흰 종이 위 먹색 글씨, 궁궐 단청의 청록 한 점. 조용하고 자신 있는, 여행 가이드북보다 잘 만든 안내판에 가까운 톤.
- 모드: 홈·모델 목록·상세 = Persuade(설득), 예약·로그인·내 예약 = Operate(작업). 작업 화면은 표현보다 빠르고 틀리지 않는 것이 우선.
- 라이트 기준. 사용 장면이 "낮에 야외에서 휴대폰을 든 관광객"이기 때문(어두운 테마는 햇빛 아래서 안 읽힌다). 어두운 면은 마무리(CTA) 한 곳에만.
- 살아 있는 요소 하나: **"Try it" 한글 번역 체험**. 홈에서 실제 한글 4개(궁궐 안내판, 메뉴, 지하철 환승 표지, 카페 주문판) 중 하나를 엄지로 누르면, 글래스가 말해 주는 영어 한 줄이 나타난다. 스크립트 없으면 한글과 영어가 나란히 보이는 정적 목록.

## 5. 간격 · 그리드 · 라운드 · 그림자

- 간격 단위 4px: `--space-1` 4 · `-2` 8 · `-3` 12 · `-4` 16 · `-5` 24 · `-6` 32 · `-7` 48 · `-8` 64 · `-9` 96 · `-10` 128 · `-11` 160 · `-12` 240
- 바깥 여백(좌우 동일, 모든 페이지 공통): `--margin: clamp(1.25rem, 3vw, 2rem)` → 20px(휴대폰) ~ 32px(데스크톱)
- 섹션 간격: `--section-gap: clamp(6rem, 4rem + 8vw, 12.5rem)` → 96px ~ 200px. 섹션 안의 어떤 간격보다 항상 크다.
- 그리드: 휴대폰 4열(간격 16) · 태블릿 768 이상 8열(간격 20) · 데스크톱 1024 이상 12열(간격 24). 콘텐츠 최대 폭 1440px, 사진·영상은 화면 끝까지.
- 브레이크포인트: 390(기준) / 768 / 1024 / 1440. **휴대폰 화면부터 그리고 확인한다.**
- 라운드: **0, 전부**. 버튼, 입력창, 사진, 영상 프레임, 바텀시트까지 직각. (경쟁사·AI 템플릿의 8~16px 둥근 모서리와 구분되는 가장 싼 방법.) 예외 없음.
- 버튼: 높이 52px(휴대폰) / 56px(데스크톱), 좌우 패딩 24px, 글자 `--step-body` 500. 터치 영역 최소 48×48.
- 그림자: 쉬는 요소에는 없음. 진짜로 떠 있는 것(바텀시트, 드롭다운, 토스트)만 `0 8px 24px rgba(18,20,22,0.16)`.
- 선: 장식 구분선 금지. 섹션 구분은 여백과 바탕 톤(`--bg`↔`--surface`)으로. 폼 입력 테두리와 실제 비교표만 `--line` 1px 허용.
- 포커스: 2px `--accent` 실선, offset 2px (다크 면 위에서는 `#FFFFFF`).
- 아이콘: 한 세트만(예: Lucide, 선 굵기 1.5, 20/24px). 아이콘 위에 색 네모 깔기 금지. 이모지 금지.

### 6-4. 예약 플로우 `/book` (Operate 모드, 휴대폰 우선)

- 구조: 한 화면에 한 질문. 위에 진행 표시는 이름으로만 `Dates · Pick-up · Your details · Pay`(현재 단계만 잉크+굵게, 나머지 `--muted`; "Step 2 of 4" 금지). 아래 **고정 바**: 왼쪽 총액(`tabular-nums`) + 오른쪽 `Continue`. 상단 요약(모델·날짜·장소)은 휴대폰에서 접힌 한 줄, 누르면 펼침.
- 모델 진입: 상세/목록에서 오면 모델이 이미 선택됨. 홈에서 오면 첫 화면이 모델 선택(사진+이름+가격 행 5개, 라디오 행).
- **날짜**: 한 달 달력(휴대폰 전체 폭, 셀 최소 44px, 직각). 수령일 → 반납일 순으로 두 번 탭. 사이 기간 `--accent-tint`, 양 끝 `--accent` 채움+흰 글자. 예약 불가 날은 `--disabled` + 취소선이 아니라 글자 흐림 + 스크린리더 "unavailable". 달력 아래 "5 days · $95" 실시간. 상단 고정 문구 "All dates and times are Seoul time (KST)." 시간대 선택은 수령 시간 슬롯(예: 10:00, 13:00, 16:00)을 버튼 행으로.
- **수령 장소**: 장소 목록(라디오 행): 장소 이름, 주소 한 줄(영문+한글 병기 — 택시 기사에게 보여 주기 용), 운영 시간, 지도 썸네일(정적 이미지, 누르면 지도 앱). 반납 장소를 다르게 할 수 있는지는 정책 확정 후(대표 확정).
- **내 정보**: 이름, 이메일, 연락 수단(WhatsApp 등 선택+번호), 동의 체크. 각 필드 위 라벨, 형식 제한은 필드 아래 상시 표시(`aria-describedby`). 오류는 필드 바로 아래 `--danger` 문장으로 "무엇이 잘못됐고 어떻게 고치는지".
- **결제**: 요약(모델·날짜·장소·대여료·보증금·총액) + 취소 규정 한 줄 링크(노션 원본 정책) + 결제 버튼. 결제 UI 자체는 PG사 화면을 따르며 디자인 대상 아님. 성공 화면은 서버 확인 후에만 보여 준다(로딩 상태 디자인 필요: "Confirming your payment…").
- **완료**: 예약 코드 크게(`--step-head`, tabular), 수령 장소·시간, `Add to calendar`, `Get directions`, 이메일 발송 안내.
- 상태 디자인 필수: 로딩(스켈레톤 대신 고정 높이 + 짧은 문장), 날짜 사이 재고 소진(다른 모델 제안), 결제 실패(다시 시도 + 연락처), 세션 만료.

### 6-5. 로그인 `/login`

- 관광객이 계정을 만들 이유가 거의 없으므로 **비밀번호 없는 방식** 제안: 이메일 입력 → `Email me a sign-in link`. 아래 두 번째 길: `Find a booking` (예약 코드 + 이메일).

## 7. 모션 원칙

| 토큰 | 값 |
|---|---|
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` |
| `--dur-fast` | 160ms (hover, press) |
| `--dur-base` | 320ms (UI 상태 전환, 바텀시트) |
| `--dur-enter` | 640ms (섹션 등장) |
| `--dur-shutter` | 1100ms (대표 모션 1회) |
| 등장 간격 | 70ms (제목 → 문장 → 사진) |
| 등장 이동 | 아래에서 24px + 투명도 |

- **대표 모션 하나**: 홈 2번 섹션 프레임이 한쪽 가장자리에서 `clip-path`로 열리며 안의 영상이 1.12 → 1.0으로 가라앉는다. 페이지에서 한 번만.
- 등장: 섹션마다 제목, 문장, 사진 순서로 70ms 간격. 한 번만 재생. 스크립트가 실패해도 내용은 보여야 한다(기본값 = 보이는 상태).
- 피드백: 모든 버튼·링크·행에 hover(색 `--accent-press`), press(`scale(0.98)`, 160ms), 포커스 링.
- 움직이는 그림은 히어로 영상 하나 + 상세 기능 루프. 그 외 장식 모션 없음.
- transform·opacity·clip-path만 움직인다. 레이아웃을 움직이지 않는다.
- 예약·로그인·내 예약 화면: 모션은 상태 전환(320ms)만. 등장 애니메이션 없음.

**prefers-reduced-motion: reduce 일 때**
- 등장 이동 없음(바로 보임), 셔터 모션 없음, press scale 없음(색 변화만).
- 2번 섹션 고정 스크롤 해제 → 세 장면을 정지 이미지 세 장으로 세로 나열.
- 히어로 영상 **자동 재생 안 함**: 포스터 이미지 + `Play video` 버튼.
- 같은 처리를 `Save-Data` 켜짐 / 느린 연결(`navigator.connection.effectiveType` 2g·3g)에도 적용(포스터만).

**영상 공통**: `autoplay muted loop playsinline`, 항상 보이는 일시정지 버튼(5초 넘게 움직이는 콘텐츠는 멈출 수 있어야 함, WCAG 2.2.2), 화면 밖으로 나가거나 탭이 숨으면 일시정지.

## 8. 히어로 영상 사양

### 촬영·편집 원칙
- **화면 위쪽 40%는 비어 있어야 한다**(하늘, 천장, 벽). h1이 그 자리에 올라간다. 피사체는 아래 55%.
- 가로판(16:9)과 세로판(9:16)을 **따로 편집**한다(세로는 가로를 잘라 내지 말고 세로 구도로 촬영 권장). 예약 대부분이 휴대폰이므로 세로판이 우선.
- 음성 없음(무음 트랙 제거). 글래스가 말하는 내용은 영상에 자막으로 굽지 않고, 사이트가 HTML 캡션으로 띄운다(번역·접근성·수정 용이).
- 광고 문구가 실제 기능과 다르면 안 된다. 각 컷의 캡션은 실제 글래스가 하는 일만.
- 마지막 컷과 첫 컷의 색·밝기를 맞춰 루프가 끊겨 보이지 않게.
- 출연자 초상권·장소 촬영 허가(경복궁은 촬영 허가 필요) 확보.
